# Project Mainline

## Research question

When evaluator verdicts enter an adaptive self-improvement loop, which errors have the largest downstream causal effect, and can those effects improve allocation of a fixed trusted-audit budget beyond static error probability alone?

## Ordered gates

1. **G1 — Paired causal identification: completed as mechanism evidence**
   - Exact clean/counterfactual prefix pairing established.
   - One delivered verdict changes persistent memory and future code.
   - Five-seed exploratory replication shows broad solution divergence without hidden-oracle accuracy harm.
2. **G1.1 — Resource-sensitive boundary test: completed, valid negative**
   - Preregistered five-seed confirmation passes every causal validity audit.
   - Explicit near-linear task contracts prevent downstream oracle and resource harm.
3. **G2 — Naturalistic matched-error benchmark: operationally closed**
   - Frozen Groq/Qwen route produced zero complete trajectories.
   - The public audit records infrastructure infeasibility, not a scientific result.
4. **G2b — Replacement instrument with unchanged research question: current gate**
   - Task-blind Gemini 3.6 Flash screen passed 24/24 calls with zero retries.
   - Model, route, task, seeds, candidates, metrics, retry policy, cost guard, and aggregate rule were frozen before real task calls.
   - No complete benchmark trajectory or research outcome exists yet; the next valid run must restart from scratch in a supported region.
5. **G3 — OOD prediction: pending**
   - Freeze a leverage estimator from isolated interventions.
   - Test held-out ranking on IID, burst, correlated, and persistent error processes.
6. **G4 — Equal-budget auditing: pending**
   - Compare random, uncertainty-only, error-probability-only, and causal-value allocation under the same trusted-audit budget.
7. **Paper gate**
   - Report positive, negative, invalid, and operationally incomplete outcomes separately.
   - Complete robustness, related work, limitations, and submission packaging.

## Anti-drift rule

Do not add new benchmarks, agent architectures, corruption families, or theory branches unless the current gate has passed or the addition is required to diagnose an operational failure without inspecting research outcomes.

Do not revise thresholds, seed sets, candidate order, outcome definitions, or the aggregate decision rule after observing task evidence. Provider-invalid trajectories are never scored as wrong model answers.
